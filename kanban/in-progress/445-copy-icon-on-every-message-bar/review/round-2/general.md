### M1 — Severity: suggestion — Status: fixed
- Verification: Read `direct-fluent-message-bar-analyzer.cs` lines 72-98 and 156-168. `ResolveHostNamespace` reads `build_property.RootNamespace` once at compilation start and returns `{RootNamespace}.Components`, or null when the property is absent or blank. `IsHostType` takes `context.ContainingSymbol`: for an invocation operation that is the enclosing member (method, field, or property), so `containingSymbol.ContainingType` is the class; the `as INamedTypeSymbol ??` arm is a harmless guard. Lambdas do not change `ContainingSymbol`, which stays the declared member. The loop walks to the outermost type, so a helper nested in `MessageBar` stays exempt. A host-named type nested inside a non-host class, such as `Other.MessageBar`, resolves to `Other` and is flagged. The namespace comparison is ordinal against `ContainingNamespace.ToDisplayString()`. With a null namespace there is no exemption (`hostNamespace is not null &&`). `RootNamespace` is compiler-visible: `source/Directory.Build.props` line 41 says it is SDK-visible, and three existing generators (`page-source-generator.cs`, `action-roster-source-generator.cs`, `state-access-source-generator.cs`) and `slice-isolation-analyzer.cs` already read `build_property.RootNamespace`. `RootNamespace` is `TimeWarp.Architecture` in `source/container-apps/Directory.Build.props`, and `web-spa.csproj` does not override it. `MessageBar.razor` and `MessageBars.razor` both declare `@namespace TimeWarp.Architecture.Components`. The template `sourceName` rewrite hits the props `RootNamespace` and the `@namespace` lines together, so they stay in agreement (the new `{RootNamespace}` comment in `MessageBar.razor` says as much). The Design region in the analyzer and in the test file both describe type identity, and neither claims path matching. In the tests, `Component()` yields `OpenComponent` on line 13 with 6 spaces of indent, so column 7, and `builder.OpenComponent<FluentMessageBar>(1)` is 42 characters, so end column 49. That matches every `Flag(path, 13, 7, 49)`. The existing `RawPage` expectation `11, 5, 47` follows the same arithmetic. Each test name matches what it does: control and host in the default namespace do not flag; the renamed root `Acme.Portal` does not flag; a host-named class in an ordinary `.cs` file does not flag (the path is not consulted); a feature `...Features.Identity.Components` namespace flags; a feature `...Features.Identity` namespace flags; `RawPage` in a host-named file flags; `MyMessageBar` flags; and no RootNamespace flags. The added `partial` on the stub `MessageBar` lets `Component(..., "MessageBar")` share the namespace without a CS0101 duplicate. Dropping the `#line`-mapped path test loses nothing that still matters: the path is no longer consulted, so mapped-path handling no longer decides the exemption. `Given_Hidden_OpenComponent_Reports_On_The_Mapped_Parameter` still covers `ReportLocation`'s mapped-location path.

### M2 — Severity: suggestion — Status: fixed
- Verification: Read `RemoveExpired` in `notification-state.cs` lines 157-166 and both new tests in `message-bar-copy-tests.cs`. `AddSuccessRowNearItsExpiry` calls the internal `AddMessage(intent, title, body, now)` with `now = UtcNow - 6s + 1s`, so `AutoDismissAt` is about UtcNow+1s. The `web-spa.csproj` `InternalsVisibleTo web-spa-integration-tests` (line 120) makes that call legal, and the named `body:` argument sits in its positional slot. `using static NotificationState` supplies `SuccessAutoDismissInterval` and `NotificationMessage`, and `MessageBarIntent` is a global using. (a) `Clear_Confirmation_When_The_Copied_Row_Expires_First`: `CopyMessage` on the row id finds the row, writes, and `MarkCopied(row.Id, UtcNow)` sets `CopiedUntil` to about now+2s. The guard assertion `AutoDismissAt < CopiedUntil` holds by construction. `ExpireMessages` at `AutoDismissAt` removes the row, and the `copiedRowExpired` clause is the only thing that clears Copied, because `CopiedUntil <= AutoDismissAt` is false. With that clause removed, `CopiedMessageId` would stay `row.Id` and `ShouldBeNull` would fail. (b) `Keep_Page_Bar_Confirmation_When_An_Unrelated_Row_Expires`: `CopyMessageBar("bar-1")` sets Copied, then the near-expiry Success row is added and expires at its `AutoDismissAt`, which is before `CopiedUntil` (the guard asserts this). No row has `Id == "bar-1"`, so `copiedRowExpired` is false and `CopiedUntil` has not passed, so `CopiedMessageId` stays `"bar-1"`. A restored "any removal clears Copied" behavior would null it and fail the test. The test file Design region documents both branches.

# Replace EnsureCreated with EF migrations for web Postgres

## Parent

147

## Description

Make **EF Core migrations** the only schema materialization path for web
`PostgresDbContext`, executed by **Aspire's first-class `AddEFMigrations` resource**
(`Aspire.Hosting.EntityFrameworkCore`) — not by the web-server at startup. Remove the
`PostgresDbContextStartupHostedService` and the interim `PostgresModelSchemaBootstrap`
"create missing tables" helper entirely: schema materialization stops being the app's job.

This is a **template** under active development — not production. Existing Aspire
volumes / dogfood DBs may be wiped once at cutover (no `__EFMigrationsHistory`); after
that, migrations accrete and dogfood data survives model changes.

Goal: grown-up schema evolution so new entities (e.g. `identity.principal_roles`)
land via committed migrations applied by the AppHost migration resource. No hand
DDL, no startup inventing tables outside migration history, and a real deploy story
(`PublishAsMigrationScript` / `PublishAsMigrationBundle`) instead of ADR-0009's
"grown apps switch to Migrate" aspiration.

## Requirements

1. **AppHost:** `AddEFMigrations` is called **on the web-server project resource**
   (not the builder), with the migrations assembly pointed at web-infrastructure:

   ```csharp
   IResourceBuilder<...> webMigrations = webServer
     .AddEFMigrations("web-migrations")            // DbContext FQN arg only if multi-context
     .WithMigrationsProject<Projects.web_infrastructure>()
     .WithReference(postgresDb)
     .WaitFor(postgresDb)
     .RunDatabaseUpdateOnStart()
     .PublishAsMigrationScript()
     .PublishAsMigrationBundle();
   webServer.WaitForCompletion(webMigrations);
   ```

   Requires a compile-only AppHost `ProjectReference` to web-infrastructure
   (`IsAspireProjectResource="false"`, same pattern as the existing contracts/analyzers
   refs in aspire-app-host.csproj). Wiring sits inside the same postgres template
   conditional as the existing `AddPostgres` wiring (TWA0010: flag present in
   DefineConstants). Resource name: local const alongside `PostgresResourceName`
   (TWA0007 only watches `AddProject` — out of analyzer scope, keep the const anyway).
2. **Remove:** `PostgresDbContextStartupHostedService` (whole file) and its registration.
3. **Remove:** `PostgresModelSchemaBootstrap` (whole file; sole call site is the hosted service).
4. **Initial migration:** full current model — `profiles`, `identity.principals`,
   `identity.credentials`, `identity.principal_roles`, and any other mapped sets.
5. **Tooling:** CPM pins for `Microsoft.EntityFrameworkCore.Design` (PrivateAssets) and
   `Microsoft.EntityFrameworkCore.Tools`; **pin `dotnet-ef` in
   `.config/dotnet-tools.json`** and document `dotnet tool restore` in the template
   story; `IDesignTimeDbContextFactory<PostgresDbContext>` in web-infrastructure whose
   contract is: **resolve the real connection string from env/config under the Aspire
   database resource name (`PostgresDatabaseResourceName` constant, i.e.
   `ConnectionStrings:<name>`), falling back to a dummy only for offline
   `migrations add` scaffolding** — a hard-coded dummy alone breaks
   `RunDatabaseUpdateOnStart`. Document the exact `dotnet ef migrations add` command
   (project, startup project, output dir, context) for agents and humans, and
   **reconcile or retire `scripts/postgres/*`** (stale `Persistence\Migrations` paths).
6. **Tests:** every fixture that calls `EnsureCreated` switches to `Migrate()` —
   `ef-principal-store-contract-tests.cs`, `ef-principal-role-store-tests.cs`, **and**
   `profile-postgres-persistence-tests.cs` (incl. renaming its
   `EnsureCreated_creates_profile_table_and_round_trips` test). Closed-box
   `aspire-tests` must still pass with the migration resource in the graph
   (`WaitForCompletion` under `Aspire.Hosting.Testing` — part of the A0 spike).
7. **Docs:** ADR-0009 golden-path text → migrations via `AddEFMigrations`;
   `how-to-add-your-aggregate.md` gains "change model → `dotnet ef migrations add` → run";
   `how-to-remove-demo-features.md` gains "regenerate/edit migrations after removing
   demo entities". Reconcile Design regions that reference EnsureCreated
   (`profile-entity-type-configuration-infrastructure.cs`,
   `principal-role-assignment-infrastructure.cs`, `postgres-db-module-server.cs` if applicable).
8. **Build 0/0** including `dev template-smoke` (change touches template-conditional
   trees; `SmokeNoPostgres` leg guards the flag wiring).

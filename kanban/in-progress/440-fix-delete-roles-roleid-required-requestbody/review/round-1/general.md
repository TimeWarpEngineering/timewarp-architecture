## Summary
The transformer fixes the stated problem, is correctly ordered, and is independent of the bearer-security and public-server transformers. No bugs found. ## Issues
### Issue 1 — Severity: suggestion
- File: tests/container-apps/web/web-server-integration-tests/open-api-delete-request-body-tests.cs:92
- Description: Only the DELETE Roles test exercises the transformer, and it covers one shape: a required `Guid` leftover property. `ClearUserXaiApiKey_Should_Stay_Without_A_Body` (line 118) and `GetRole_Should_Keep_UserId_On_The_Query_String` (line 108) describe behavior that exists without the transformer. FastEndpoints already omits the body for a DELETE with no leftover properties and already promotes GET properties. They guard against collateral change but cannot catch a regression in the new code. The Design region (open-api-delete-request-body.cs:11-13) makes concrete claims that nothing tests: a leftover object or collection keeps the body with `required: false`, and nullable properties publish `required: false`. The test also does not check `HasParameter` de-duplication or `[JsonIgnore(Always)]` skipping.
- Suggestion: Add a synthetic DELETE FastEndpoint to the test assembly and include it in `EndpointNames`. Give its request type a route id, an optional scalar, and a variant with a complex property. Assert that the optional property publishes `required: false` and that a complex property keeps the body with `required: false`. This is optional. The primary path is covered and the red check was done.
- Status: open

### Issue 2 — Severity: nit
- File: source/foundation/foundation-server/open-api-delete-request-body.cs:309
- Description: The `SchemaFor` fallback is inaccurate for types that `IsScalar` accepts (lines 245-259). `DateOnly` is mapped to `format: date-time` (line 322), but it should be `date`. `uint`, `ulong`, `ushort` and `sbyte` are not in the integer list at line 332, so they become `type: string`. Enums fall through to plain `string`, so enum values or an integer-backed representation are lost. `TimeOnly` and `TimeSpan` become bare strings, which is acceptable. The fallback runs only when `BodyPropertySchema` finds nothing. The Guid case that the test checks gives the same `uuid` result on either path, so the test cannot show which path produced it. Also note that `Resolve` reads `OpenApiSchemaReference.Target`. I did not verify whether `Target` is populated at operation-transformer time.
- Suggestion: Fix `DateOnly` to `format: date`. Handle unsigned and signed-byte integers. Optionally, when the body lookup fails for an enum, emit `type: string` with the enum names, or at least state in the Design region that the fallback is approximate.
- Status: open

## Facts checked
- Ordering and interaction: `OpenApiBearerSecurity` (open-api-bearer-security-server.cs:91-117) and `OpenApiPublicServer` (open-api-public-server.cs:35) do not read `RequestBody` or `Parameters`. They only set `Security`, responses and description, and `servers`. Registration order at common-server-module.cs:153-160 is therefore safe. The bearer transformer uses `SingleOrDefault` on `EndpointDefinition` and the new one uses `FirstOrDefault`. This is harmless.
- Readonly `Parameters`: line 76 handles both a null list (`null != false` is true, so a new list is created) and a read-only list (copied). A mutable list is used as is. Correct.
- Route-name parsing (lines 160-203): handles `{id:guid}`, `{id?}`, `{**x}` and `{id=5}`. Nested braces in a regex constraint, such as `{id:regex(\d{3})}`, would mis-tokenize. Impact is nil, because the path parameter FastEndpoints already added makes `HasParameter` (lines 205-221, case-insensitive) skip the property. The scalar-only `IsScalar` check also keeps such a property from forcing the "complex" branch.

A complex type returns null and the body is kept with `required: false`, which matches the Design region (lines 11-13). The query name is `JsonPropertyName` or camelCase. `HttpApiService` sends `UserId` in PascalCase (delete-role-contracts.cs:47).

## Prior findings
### M1 — Severity: suggestion — Status: fixed
- Verification: `Optional_Scalars_Should_Publish_Optional_Query_Parameters` (tests file :115) targets `DeleteProbeOptionalEndpoint` (`Id` in the route, `int? Limit`, `string? Note`). It asserts that `requestBody` is absent, `id` is a required path parameter, and `limit` and `note` are query parameters with `required` false or omitted. Without the transformer, FastEndpoints publishes the leftover properties in the body, so `requestBody` would exist and `Parameter(operation, "limit", "query")` would throw "Missing query parameter". Both assertions are therefore red-capable. The transformer's `Required = !IsOptional(property)` (source :100) is the line that sets `required` on the query parameters. `Collection_Property_Should_Keep_An_Optional_RequestBody` (:125) targets `DeleteProbePayloadEndpoint` (`Guid Id` plus `IReadOnlyList<Guid> Items`). `Items` fails `IsScalar`, so `QueryProperties` returns null and the transformer sets `requestBody.Required = false` (source :71-76). The test asserts the body is present and `IsRequired` is false. With the transformer absent or forcing `required: true`, the body would be required and the test would fail. The `IsRequired` helper treats an omitted `required` key as false, which is correct because the OpenAPI writer drops a false boolean. It is also consistent with the existing roleId and userId assertions, which require the key to be present and true. Both probes use `AllowAnonymous`, and the bearer-security transformer returns early for them because they have no agent auth scheme (source open-api-bearer-security-server.cs:107).

### M2 — Severity: nit — Status: fixed
- Verification: In `SchemaFor` (source :312-363), `DateOnly` now maps to `date`, `TimeOnly` to `time`, and `DateTime` and `DateTimeOffset` stay `date-time`. `sbyte`, `ushort`, `uint` and `ulong` are now in the integer branch alongside `byte`, `short`, `int` and `long`. Every type `IsScalar` accepts is covered. Enum and `TimeSpan` fall through to plain `string`, and the Design region (source :14-16) documents that the enum fallback has no values because the app's JSON options own the enum wire format. That is the second option M2 offered. The fallback itself is still not directly tested, because the body schema is normally found first. Round 1 asked for no test of it, so this is a fact and not an issue.

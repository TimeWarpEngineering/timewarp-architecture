## Issues
### Issue 1 — Severity: suggestion
- File: source/analyzers/timewarp-architecture-convention-analyzers/iso-date-rendering-analyzer.cs:273-278 (and Design region lines 18-22)
- Description: `IsInInvariantInterpolation` exempts a hole whenever its interpolated string is the direct argument of any invocation that also receives an invariant `IFormatProvider`. That is only correct when the interpolated string is bound to a handler that takes the provider (`string.Create`, `StringBuilder.Append(provider, …)`). When the parameter is `string`, `object`, or `FormattableString` (other than `FormattableString.Invariant`), the string is built under the current culture and the provider only affects the callee, so the hole is a false negative. Example: `Foo(CultureInfo.InvariantCulture, $"{at:yyyy-MM-dd}")` with `Foo(IFormatProvider, string)`: the hole is an `IInterpolationOperation`, its parent is the `IArgumentOperation`, `HasInvariantProviderArgument(call)` is true, and no diagnostic is raised. The Design region sentence "any invocation that passes the invariant provider to an IFormatProvider parameter" repeats the over-claim.
- Suggestion: Only accept the provider-call exemption when the climb passed through an `IInterpolatedStringHandlerCreationOperation`, or when that argument's parameter type has `[InterpolatedStringHandler]`. Keep `FormattableString.Invariant` as a separate method-name check. Add a test row such as `Parse($"{at:yyyy}", CultureInfo.InvariantCulture)` or a `Foo(IFormatProvider, string)` stub that must flag, and tighten the Design sentence.
- Status: open

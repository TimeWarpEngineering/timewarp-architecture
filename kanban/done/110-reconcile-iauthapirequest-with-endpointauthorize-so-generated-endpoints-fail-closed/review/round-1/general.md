## Issues

### Issue 1 — Severity: suggestion
- File: source/container-apps/web/web-contracts/features/admin/roles/commands/create-role.cs:23 (same literal in update-role.cs, delete-role.cs, get-role.cs, get-roles.cs; constant at source/container-apps/web/web-server/configuration/identity-session-defaults.cs:30)
- Description: The policy name `"identity-session-authenticated"` now exists as six independent strings that must agree — five raw literals in web-contracts (each with a `// matches IdentitySessionDefaults.AuthenticatedPolicy` comment) plus the web-server constant — held together by comments alone. The Design regions honestly record why (web-contracts cannot reference web-server; the dependency runs the other way), and the failure mode is fail-closed-and-loud for these five (a typo'd policy name generates `Policies("...")` for a policy that was never registered, so every request 403s at runtime and `Roles_Authorization_Tests` catches it). But for FUTURE contracts naming future policies there is no build-time agreement check, and this is precisely the repo's standing prefer-analyzers trigger ("when two things must agree, generate one from the other or add a build-time check"). A misspelled policy on a new contract compiles 0/0, passes TWA0013/0014, and fails only when someone drives the endpoint over HTTP.
- Suggestion: Record a candidate follow-up analyzer/check (e.g. a web-server-side compilation check that every `Policies(...)` name emitted by generated endpoints appears in the set of registered policy names, or a shared attributes-package constants class both sides can reference). A kanban note suffices; not blocking.
- Status: open

### Issue 2 — Severity: nit
- File: source/analyzers/timewarp-architecture-convention-analyzers/endpoint-auth-posture-analyzer.cs:64-74 (messageFormat at line 69)
- Description: TWA0014's `DiagnosticDescriptor` uses `messageFormat: "{0}"` with fully-composed sentence arguments — a passthrough pattern no sibling analyzer uses (all others carry structured formats with data-only args, e.g. AggregateInvariantsAnalyzer, EndpointCoverageAnalyzer). Consequences are cosmetic but real: anything that renders the descriptor's `MessageFormat` (rule documentation generators, IDE rule metadata) shows a bare `{0}`, and the two TWA0014 sub-shapes are distinguishable only by free-text comparison rather than by format structure.
- Suggestion: Either split into two structured formats selected at report time (Roslyn supports multiple `Diagnostic.Create` calls sharing an ID with different descriptors is NOT allowed — instead use one format with placeholders like "Contract '{0}' has a contradictory auth posture: {1}"), or keep as-is and accept the cosmetic cost — worth aligning if the file is touched again, not on its own.
- Status: open

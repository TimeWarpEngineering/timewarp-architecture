## Summary
The dual-mode package-switch machinery, the three families' filename-grammar/membership generation, `template.json`'s exclude lists, and version alignment (source `2.0.0-beta.17` vs latest published tag `v2.0.0-beta.16`) are all internally consistent — no unused CPM pins, no duplicate pins, no dangling `template.json` paths, no unbalanced `#if`/`#endif`. The main findings are solution-membership gaps: `web-spa.csproj` (the actual SPA product project) and `tests/tools/agent-identity-cli-tests` are absent from `timewarp-architecture.slnx` with no documented rationale (unlike the JARIBU_MULTI aggregators and `timewarp-testing-tests`, which do carry an explicit "intentionally excluded" comment), plus one dangling CI path filter and one dead versioning file in `timewarp-templates/`.

## Issues

### Issue 1 — Severity: suggestion
- File: `timewarp-architecture.slnx` (whole file — `web-spa` is never listed, e.g. contrast with lines 41-45)
- Description: `source/container-apps/web/projects/web-spa/web-spa.csproj` — the Blazor WASM SPA that is the actual web client product — has never been a member of the solution (confirmed via `git log -p --follow` on the slnx: only its test project, `web-spa-integration-tests`, was ever added). It is still built today only because `web-server.csproj` carries a `ProjectReference` to it (`source/container-apps/web/projects/web-server/web-server.csproj:65`), so `dotnet build` on the slnx compiles it transitively. But it means an IDE/Solution Explorer view of the repo never shows the SPA project, and any tooling that trusts slnx membership as "the buildable project set" undercounts it.
- Suggestion: Add `web-spa.csproj` under the `(web)` `#if` block in the slnx alongside the other web layer projects, or add a comment next to the `(web)` block explaining why it's deliberately left out (e.g. "built transitively via web-server").
- Status: open

### Issue 2 — Severity: suggestion
- File: `timewarp-architecture.slnx`; `tests/tools/agent-identity-cli-tests/agent-identity-cli-tests.csproj`
- Description: `tests/tools/agent-identity-cli-tests` is a normal suite-shaped Jaribu MTP test project (its `global.json` sets `"test": {"runner": "Microsoft.Testing.Platform"}` the same as every other in-slnx suite) but is not in the slnx at all — there isn't even a `/tests/tools/` folder entry to hold it. Unlike `tests/common/timewarp-testing-tests/timewarp-testing-tests.csproj`, which carries an explicit code comment saying it mirrors the task-136 family-aggregator pattern and is deliberately excluded, this project carries no such rationale. `dev test` still runs it (it globs `tests/**/*.csproj` directly rather than reading the slnx), but `dev build`'s 0/0-warnings gate never compiles it since it builds the slnx.
- Suggestion: Add it to the slnx (new `/tests/tools/` folder, gated by `(true)` or ungated since `agent-identity-cli-tests` is monorepo-only per `template.json`'s exclude list) or add a comment matching `timewarp-testing-tests`' pattern if the omission is deliberate.
- Status: open

### Issue 3 — Severity: nit
- File: `.github/workflows/workflow.yml:24` (push paths) and `:41` (pull_request paths) and `:110` (detect-paths shell filter)
- Description: All three path filters include `Directory.Version.props`, but no such file exists anywhere in the repo (verified with `find`). It's a harmless dead pattern — it will just never match — left over from either a rename or a file that was never created.
- Suggestion: Remove `Directory.Version.props` from the three path-filter lists, or if it was meant to replace `source/Directory.Build.props`'s `<Version>` element as a dedicated version file, create it and wire it in.
- Status: open

### Issue 4 — Severity: nit
- File: `timewarp-templates/version.json`
- Description: This is a Nerdbank.GitVersioning config file (`version: "1.0-beta"`, `publicReleaseRefSpec`), but no project under `timewarp-templates/` references the `Nerdbank.GitVersioning` package, and nothing in `tools/dev-cli` or `.github/workflows/workflow.yml` reads this file. The actual template package version comes from `timewarp-templates/Directory.Build.props`'s own `<Version>2.0.0-beta.17</Version>` (which is correctly kept in sync with the root `source/Directory.Build.props` version — both matched at the time of this review). `version.json`'s `1.0-beta` value is stale/misleading relative to the real `2.0.0-beta.17`.
- Suggestion: Delete `timewarp-templates/version.json` (dead config), or wire it up if NBGV is actually intended for this tree.
- Status: open

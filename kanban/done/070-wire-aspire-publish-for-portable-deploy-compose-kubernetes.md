# Wire Aspire publish for portable deploy (Docker Compose + Kubernetes)

Build-out follow-up to [[063-relocate-devops-deploy-infra-to-root]], which removed the
hand-rolled Azure-locked DevOps tree.

## Goal

A **portable** deploy story driven entirely by the Aspire AppHost: deploy the same app to
**standalone hardware**, **on-prem Kubernetes**, or **Azure** with no Azure lock-in. The AppHost
(`source/container-apps/aspire/projects/aspire-app-host/program.cs`) is the single source of truth;
every deployment artifact is GENERATED by `aspire publish` / `aspire deploy`.

## Rewrite (2026-10-03, cockpit + Steve)

The original spec was written against Aspire 13.4. The repo is on **Aspire 13.6** (task 262) and
the platform moved:

- **Kubernetes now publishes a Helm chart, not raw manifests** (`Chart.yaml`, `values.yaml`,
  `templates/<resource>/{deployment,service,config}.yaml`). `aspire deploy` runs `helm install`
  (`helm upgrade` afterwards) against the current kubectl context.
  - Requires **Helm ≥ 4.2**.
  - A vanilla cluster needs `AddContainerRegistry(...)` + `WithContainerRegistry(...)` (preview,
    `ASPIRECOMPUTE003`).
  - `WithHelm`, `PublishAsKubernetesService`, persistent-volume docs, and `AddHelmChart` for
    ingress-nginx / cert-manager now exist.
  - See aspire.dev `deploy-to-kubernetes-clusters`.
- **Azure has dedicated targets** (AKS, Azure Container Apps, and ACA Sandboxes in 13.6), so
  "Azure = the same K8s manifests" no longer holds. That decision moves to the guidance child.
- **No new docs tree.** `documentation/` is retired, and skills plus Design regions are the record.
  The original "root `devops/` + `README.md`" is replaced by a skill (070-005) and the AppHost Design
  region. Whether generated artifacts are committed at all is decided in 070-003 (default: CI output,
  not committed).
- **Acceptance is publish-output checks in CI, not a kind smoke-deploy.** Workers cannot run
  clusters or AppHosts. A real kind or cluster deploy is the maintainer's check. Child 070-001
  (public kind exposure) was retired on 2026-09-21 as operator infrastructure.
- **Container runtime neutrality.** WSL containers went GA on 2026-09-29 and Aspire is adding
  support (task 277). Generated Compose output is a standard `compose.yaml`. Dev tooling added here
  must go through the Aspire runtime setting and never hard-code the `docker` CLI.

## Target matrix (Aspire 13.6)

| Target              | Environment in AppHost        | Artifact                    | Run with                                   |
|---------------------|-------------------------------|-----------------------------|--------------------------------------------|
| Standalone hardware | `AddDockerComposeEnvironment` | `compose.yaml` (+ `.env`)   | `docker compose up` / Podman / `wsl compose` (when shipped) |
| On-prem Kubernetes  | `AddKubernetesEnvironment`    | Helm chart                  | `aspire deploy` or `helm install/upgrade`  |
| Azure               | decided in 070-005            | AKS chart or ACA            | `aspire deploy`                            |

## Cross-cutting requirements (all children)

- Template-flag aware: the AppHost uses `#if api/web/grpc/yarp/postgres`. Publish wiring must keep
  every flag combination valid, and `dev template-smoke` must stay green.
- **Production safety in generated output** (verified by tests that inspect publish output):
  - mock auth never activates (`Authentication:UseMock` posture, task 145-009);
  - browser-log forwarding (task 261) is absent;
  - the dashboard REPL (`WithRepl`, Development-only, task 262) is absent;
  - Entra and other secrets are **parameters/secrets**, never literals;
  - only the ingress is externally exposed.
- Postgres: persistent storage, a secret password parameter, and migrations via the existing
  `PublishAsMigrationScript` / `PublishAsMigrationBundle` (task 155). Define how they run in each
  target.
- Workers never start the maintainer's AppHost or touch the maintainer's Docker volumes.

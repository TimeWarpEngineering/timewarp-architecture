## Prior findings
### M2 — Severity: suggestion — Status: fixed
- Evidence:
  - (a) `Every_Problem_Arm_Endpoint_Should_Publish_Default_Problem` (open-api-one-of-tests.cs:133-166) iterates `((IEndpointRouteBuilder)App!).DataSources` -> `RouteEndpoint`, takes `EndpointDefinition` metadata, and keeps those whose `ResDtoType` is a OneOf with a `SharedProblemDetails` arm (`HasProblemArm`, :272-284). It then looks each operation up in the document and requires `default` -> `application/problem+json` -> `$ref` == `ProblemSchema` (:153-157). A missing path, a missing `default`, or a wrong schema goes into `missing` (:159) and fails at :165. It starts from endpoint metadata, not the document, so an operation that loses `default` fails.
  - Route normalisation: `RouteConstraint()` (`\{([^}:=?]+)[^}]*\}` -> `{$1}`, :286) turns `api/Feedback/{FeedbackItemId:guid}` into `/api/Feedback/{FeedbackItemId}`, which is the form the OpenAPI document keys use. It also handles `?`, `=` defaults, and multi-segment routes. Every parameterised `[ApiRoute(` in source/ uses only `{Name:guid}` (e.g. get-feedback-contracts.cs:25, revoke-credential-contracts.cs:37, set-principal-roles-contracts.cs:26). `TrimStart('/')` plus `"/" +` makes the leading slash uniform, and `TryGetOperation` compares OrdinalIgnoreCase (:308). A mapping miss fails closed (the operation lands in `missing`), it cannot silently pass. `RawText!` is non-null for FastEndpoints-built patterns. The implementer reports 73 operations checked (task.md Results -> Fix pass).
  - (b) `OneOfProbeProblemStatusEndpoint` (:380-396) adds `ProducesProblem(StatusCodes.Status422UnprocessableEntity)`, so the response `422` carries `application/problem+json`. That is exactly the shape the rewrite loop at open-api-one-of.cs:174-181 matches (4xx key plus `ProblemJson` content). `Explicit_Problem_Status_...` (:168-175) asserts the 422 `$ref` is `ProblemSchema`, so it fails if the loop is skipped. The implementer's negative control reports 1 of 9 failing when only the 4xx rewrite is skipped (task.md Results).
  - (c) `Union_Without_Problem_Arm_Should_Stay_OneOf_At_200` (:177-192) uses `OneOf<Cat, Dog>` (:398-413). `Arms` is non-null and `problemIndex` is -1, so the transformer returns at open-api-one-of.cs:138-141. The test asserts `oneOf` with exactly the Cat and Dog refs at 200 and `default` absent (:191). That pins the intended behaviour.
- Remaining weakness is the sanity bound only, see N1.

### M3 — Severity: suggestion — Status: fixed
- Evidence:
  - Schema guard (open-api-one-of.cs:100-116): a missing `asT{n}` throws `InvalidOperationException` naming `unionType` and the member. `schema.Properties?` is null-safe, so a null `Properties` now also throws instead of returning early (previously `schema.Properties is null` returned silently). That is the intended stricter behaviour.
  - Operation guard (:164-172): `problem is null || operation.Responses is null` throws. The message names `HttpMethod`, `/RelativePath`, `endpoint!.ResDtoType`, and `arms.Length`. `arms.Length` is the full arm count including the problem arm, which matches the `union.Count != arms.Length` comparison at :153, so the wording "oneOf over its N arms" is accurate. `endpoint!` is safe because `arms` non-null implies `endpoint` non-null (:136-141). `RelativePath` has no leading slash, so the added `/` is right.
  - `operation.Responses ?? []` at :144 with `Responses` null falls through to `problem is null` and the throw, so a null `Responses` on a problem-arm endpoint throws rather than no-ops. The later `operation.Responses` dereferences at :174 and :183 are behind that throw.
  - `union.Count != arms.Length` still `continue`s (:153-156), but if no 2xx matches, `problem` stays null and the throw fires. The only remaining quiet path is a partial mismatch: one 2xx media type matches and another 2xx does not (the other keeps its unrewritten union). Not reachable for any in-repo endpoint; mention only.
  - Design region (open-api-one-of.cs:17-19, :26-27, :29-32) says the schema guard throws naming the type, the operation guard throws naming the endpoint, and why: a naming or package change would otherwise republish the wrapper silently, and the throw makes `/openapi/{doc}.json` return 500 with the cause. The implementer's negative control (renamed member to `asX{n}`) reports the document request throwing with the message and every document test failing with it (task.md Results). `DocumentRootAsync` now puts up to 2000 chars of the body into the status assertion message (tests:320-328), so the cause is visible in the test failure.
